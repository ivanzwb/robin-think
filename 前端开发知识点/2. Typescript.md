### 🧭 TypeScript 学习总览

这份文档采用单层学习结构，每个模块直接包含知识点、讲解和示例，涵盖从基础类型到工程落地的完整路径。

### 📊 学习路径建议

1. 先学模块一和模块二，建立类型系统基础与建模能力。
2. 再学模块三和模块四，掌握泛型与类型运算（类型层编程）。
3. 再学模块五和模块六，把类型能力落到工程和框架实战。
4. 最后学模块七，形成排错和类型治理能力。

### 🎯 学习目标

- 能解释 TypeScript 的价值在于编译期约束，而不是运行时替代 JavaScript。
- 能熟练使用类型建模、泛型、联合收窄和类型运算表达真实业务结构。
- 能说清类型擦除、控制流分析、模块解析这些底层机制为何影响日常开发。
- 能把 TS 能力落到工程配置、声明文件和框架实战场景中。

### 📐 模块一：类型系统基础

- **知识点**：基础类型、特殊类型、类型推断、类型断言、字面量类型、类型守卫、编译期与类型擦除。
- **模块讲解**：
    - TS 在编译期做静态检查，运行时删除所有类型注解，不改变 JS 执行机制。
    - `unknown` 比 `any` 更安全，使用前必须类型守卫。
    - `never` 用于表示不可能到达的分支，也是递归底部的标记。
    - 字面量类型精确表达值的范围，比宽泛类型更安全。

#### 1.1 基础类型与特殊类型

- **讲解**：
    - `any` 绕过所有类型检查，应该尽量避免。
    - `unknown` 是"未知类型"，必须先类型守卫再使用。
    - `never` 表示永不返回，用于异常、无限循环、穷尽检查。
    - `void` 用于无返回值函数。
- **示例**：

```ts
function processInput(input: unknown): string {
  if (typeof input === 'string') {
    return input.toUpperCase();
  } else if (typeof input === 'number') {
    return input.toString();
  }
  const _exhaustive: never = input; // 编译器检查是否穷尽了所有情况
  return _exhaustive;
}

function throwError(msg: string): never {
  throw new Error(msg);
}

function infiniteLoop(): never {
  while (true) {}
}
```

#### 1.2 类型推断与 const 断言

- **讲解**：
    - 类型推断让代码更少冗余，同时保持安全。
    - `as const` 让对象/数组的每个属性都成为字面量类型。
    - 避免手工断言，优先让 TS 自动推断。
- **示例**：

```ts
const arr = [1, 2, 3]; // 推断为 number[]
const arr2 = [1, 2, 3] as const; // 推断为 readonly [1, 2, 3]

const obj = { name: 'tom' }; // name 推断为 string
const obj2 = { name: 'tom' } as const; // name 推断为 'tom'

type Status = 'active' | 'inactive';
const status: Status = 'active'; // 无需 as
```

#### 1.3 类型转换与类型谓词

- **讲解**：
    - 类型转换（as）是"告诉编译器"，运行时无效。
    - 类型谓词（is）用于自定义守卫函数。
    - 不要过度转换，类型转换失败是常见错误来源。
- **示例**：

```ts
// 类型转换（not safe）
const input: unknown = 'hello';
const str = input as string; // 编译通过但可能运行时错误

// 类型谓词（safe）
function isString(value: unknown): value is string {
  return typeof value === 'string';
}

if (isString(input)) {
  console.log(input.toUpperCase()); // 类型已收窄为 string
}
```

#### 1.4 TypeScript 编译器、类型擦除与为什么运行时看不到类型

- **讲解**：
    - TypeScript 编译器大致会经历 parse、bind、check、emit 几个关键阶段：先解析源码，再建立符号表，再做类型检查，最后输出 JavaScript。
    - 大多数类型信息只存在于 check 阶段，emit 输出时会被擦除，所以运行时不会保留 `interface`、泛型参数、类型别名等概念。
    - 这就是为什么 TS 能帮你在开发期发现错误，却不能自动替代运行时校验。
    - 面试里如果只会说“TS 是 JS 超集”，但说不清“为什么运行时看不到类型”，通常说明没有真正理解编译期边界。
- **示例（编译前后）**：

```ts
// input.ts
function add(a: number, b: number): number {
  return a + b;
}
```

```js
// output.js
function add(a, b) {
  return a + b;
}
```

- **理解重点**：
    - 类型系统主要服务编辑器、构建和 CI。
    - 运行时边界仍需 schema 校验、守卫函数或业务校验逻辑兜住。

### 🧱 模块二：类型定义与建模

- **知识点**：`interface`、`type`、结构化类型、函数与类类型、可选与只读修饰符。
- **模块讲解**：
    - `interface` 适合对象契约和声明合并。
    - `type` 更适合联合、交叉、映射等复杂类型表达。
    - TS 是结构化类型系统，关注"结构兼容"而不是"名称一致"。
    - 修饰符 `?`（可选）和 `readonly` 用于细粒度控制。

#### 2.1 Interface vs Type

- **讲解**：
    - `interface` 支持声明合并和继承，适合模型契约。
    - `type` 支持联合、交叉、映射，更灵活。
    - 新项目可优先 `type`，必要时再用 `interface`。
- **示例**：

```ts
// 声明合并（仅 interface 支持）
interface User {
  id: string;
  name: string;
}

interface User {
  email: string; // 合并到同一个 User
}

// 复杂类型（type 更直观）
type Result<T> =
  | { status: 'ok'; data: T }
  | { status: 'error'; message: string };

type Admin = User & { role: 'admin' };
```

#### 2.2 结构化类型与兼容性

- **讲解**：
    - TS 比较"形状"（shape），不比较名称。
    - 多余属性在赋值时会被检查，但 interface 通常更宽松。
- **示例**：

```ts
interface Point {
  x: number;
  y: number;
}

const p: Point = { x: 1, y: 2, z: 3 }; // error: 多余属性

// 但如果先赋给变量再传入，则通过
const obj = { x: 1, y: 2, z: 3 };
const p2: Point = obj; // ok（鸭子类型）
```

#### 2.3 函数与类的类型

- **讲解**：
    - 函数类型分声明和表达式两种写法。
    - 类可实现 `interface`，也可用 `type` 约束。
- **示例**：

```ts
// 函数声明
function add(a: number, b: number): number {
  return a + b;
}

// 函数表达式
const subtract: (a: number, b: number) => number = (a, b) => a - b;

// 类
interface Animal {
  name: string;
  speak(): void;
}

class Dog implements Animal {
  name: string;
  constructor(name: string) {
    this.name = name;
  }
  speak() {
    console.log(\`\${this.name} barks\`);
  }
}
```

### 🔗 模块三：泛型、联合与收窄

- **知识点**：泛型约束、泛型默认值、联合类型、类型守卫、可辨识联合、in 操作符、控制流分析。
- **模块讲解**：
    - 泛型用于"延迟确定类型"，提升复用能力。
    - 联合类型必须先收窄再安全访问。
    - 可辨识联合（判别式模式）是前端状态建模的核心手段。

#### 3.1 泛型基础与约束

- **讲解**：
    - 泛型参数可通过 `extends` 约束。
    - 可设置泛型默认值，简化使用。
- **示例**：

```ts
function pickFirst<T>(arr: T[]): T | undefined {
  return arr[0];
}

// 泛型约束
function merge<T extends object, U extends object>(a: T, b: U): T & U {
  return { ...a, ...b } as T & U;
}

// 泛型默认值
type Container<T = string> = { value: T };
const s: Container = { value: 'hello' };
const n: Container<number> = { value: 42 };
```

#### 3.2 联合类型与可辨识联合

- **讲解**：
    - 联合类型表示多种可能，必须收窄后才能安全访问。
    - 可辨识联合通过一个公共字段区分各分支，比 `typeof` 守卫更清晰。
- **示例**：

```ts
// 简单联合
let value: string | number;
if (typeof value === 'string') {
  console.log(value.toUpperCase());
}

// 可辨识联合（推荐用于复杂状态）
type Result =
  | { kind: 'ok'; data: string }
  | { kind: 'error'; message: string }
  | { kind: 'pending' };

function handle(res: Result) {
  switch (res.kind) {
    case 'ok':
      console.log(res.data);
      break;
    case 'error':
      console.error(res.message);
      break;
    case 'pending':
      console.log('waiting...');
      break;
  }
}
```

#### 3.3 类型守卫与 in 操作符

- **讲解**：
    - 类型守卫用于运行时判断，帮助 TS 收窄类型。
    - `in` 操作符检查属性存在性，比 `typeof` 更精细。
- **示例**：

```ts
interface Bird { fly: () => void }
interface Fish { swim: () => void }

function move(animal: Bird | Fish) {
  if ('fly' in animal) {
    animal.fly(); // 收窄为 Bird
  } else {
    animal.swim(); // 收窄为 Fish
  }
}
```

#### 3.4 控制流分析：TS 为什么能顺着分支收窄类型

- **讲解**：
    - TypeScript 不只是看某一行声明，还会顺着 if/switch/return/throw 这些控制流路径推断某个变量在当前位置可能是什么类型。
    - 这套机制叫 control flow analysis，它解释了为什么同一个变量在不同分支里能被视为不同类型。
    - 一旦某个分支提前 return 或 throw，编译器会认为剩余路径里某些类型已经被排除。
- **示例**：

```ts
function printId(id: string | number | null) {
  if (id == null) {
    return;
  }

  if (typeof id === 'string') {
    console.log(id.toUpperCase());
    return;
  }

  // 走到这里时，id 自动收窄为 number
  console.log(id.toFixed(2));
}
```

- **理解重点**：
    - 收窄不是“魔法”，而是编译器在跟踪程序路径。
    - 这也是为什么复杂业务状态建模时，`kind/status/type` 这类判别字段特别重要。

### 🧮 模块四：类型运算与工具类型

- **知识点**：`keyof`、`typeof`、条件类型、`infer`、映射类型、模板字面量类型、递归类型。
- **模块讲解**：
    - 类型运算本质是"在类型层做程序设计"。
    - 条件类型可表达输入输出关系，`infer` 用于提取子类型。
    - 工具类型常用于 DTO 变形与 API 契约维护。

#### 4.1 keyof 与 typeof

- **讲解**：
    - `keyof T` 获取对象类型的所有键组成的联合。
    - `typeof v` 获取变量的类型。
- **示例**：

```ts
interface User {
  id: string;
  name: string;
  age: number;
}

type UserKeys = keyof User; // 'id' | 'name' | 'age'

const obj = { x: 1, y: 2 };
type ObjType = typeof obj; // { x: number; y: number }
```

#### 4.2 条件类型与 infer

- **讲解**：
    - 条件类型类似三元表达式，用于类型分支。
    - `infer` 用于在条件类型中提取和保存子类型。
- **示例**：

```ts
type UnwrapPromise<T> = T extends Promise<infer U> ? U : T;
type PromiseString = UnwrapPromise<Promise<string>>; // string
type PlainString = UnwrapPromise<string>; // string

// 提取函数参数类型
type GetFirstArg<T> = T extends (arg: infer A, ...args: any[]) => any ? A : never;
type FirstArg = GetFirstArg<(x: string, y: number) => void>; // string
```

#### 4.3 映射类型与工具类型

- **讲解**：
    - 映射类型通过 `keyof` 和 `in` 遍历，可变形所有属性。
    - TS 内置工具：`Pick`、`Partial`、`Required`、`Readonly`、`Record`、`Omit` 等。
- **示例**：

```ts
// 自定义映射类型
type Getters<T> = {
  [K in keyof T]: () => T[K];
};

interface User {
  name: string;
  age: number;
}

type UserGetters = Getters<User>;
// {
//   name: () => string;
//   age: () => number;
// }

// 使用工具类型
type UserPreview = Pick<User, 'name'>;
type PartialUser = Partial<User>;
type ReadonlyUser = Readonly<User>;
```

#### 4.4 模板字面量类型

- **讲解**：
    - 模板字面量在类型层面，可组合字符串字面量。
    - 适用于 API 路由、事件名等。
- **示例**：

```ts
type Method = 'GET' | 'POST' | 'PUT';
type Route = 'users' | 'posts';
type Endpoint = \`\${Method} /api/\${Route}\`; // 'GET /api/users' | 'GET /api/posts' | ...

// 事件类型
type Events = 'user-created' | 'user-deleted';
type Handler<T extends Events> = T extends \`\${infer Entity}-\${infer Action}\`
  ? { entity: Entity; action: Action }
  : never;
```

### ⚙️ 模块五：工程配置与声明文件

- **知识点**：`tsconfig` 配置、严格模式选项、`.d.ts` 声明文件、`satisfies`、类型导入导出、模块解析。
- **模块讲解**：
    - `strict` 是大型项目可维护性的基础，不建议关闭后"裸奔"。
    - `.d.ts` 用于描述运行时代码的类型契约，也可发布纯类型包。
    - `satisfies` 可用于"校验约束但保留更精确推断"，避免过度宽泛。

#### 5.1 tsconfig 与严格模式

- **讲解**：
    - `strict: true` 启用多个严格检查选项。
    - `noImplicitAny` 禁止隐含 `any`。
    - `noNullishCoalescing` 禁止可选链可能返回 `null`。
- **示例**：

```json
{
  "compilerOptions": {
    "strict": true,
    "noImplicitAny": true,
    "strictNullChecks": true,
    "moduleResolution": "node",
    "target": "ES2020",
    "module": "ESNext"
  }
}
```

#### 5.2 声明文件与 .d.ts

- **讲解**：
    - `.d.ts` 文件只包含类型定义，不包含实现。
    - 用于为 JS 库提供类型支持。
    - 可通过 `dts` 工具自动生成。
- **示例**：

```ts
// util.d.ts
export function add(a: number, b: number): number;
export const version: string;

export interface Config {
  timeout: number;
  retries: number;
}
```

#### 5.3 satisfies 操作符与类型导入

- **讲解**：
    - `satisfies` 校验值符合类型，但保留推断出的精确类型。
    - `import type` 仅导入类型，不导入运行时值。
- **示例**：

```ts
const routes = {
  home: '/',
  profile: '/profile/:id'
} satisfies Record<string, string>;

type RouteName = keyof typeof routes; // 'home' | 'profile' （精确推断）

// 类型导入
import type { User } from './user';
export type { User };
```

#### 5.4 模块解析与声明合并：为什么“能找到类型”这件事并不简单

- **讲解**：
  - TypeScript 在解析 import 时，不只是找 `.ts` 文件，还会结合 `package.json`、`types` 字段、`exports`、路径别名、`node_modules` 和 `.d.ts` 文件一起决定最终类型来源。
  - 这就是为什么同一个包“运行时能 import 成功，但类型提示不一定正常”；因为值解析和类型解析虽然相关，但不是完全等价的一步。
  - 另外，`interface` 支持声明合并，本质是编译器在 bind/check 阶段把多个同名声明并进同一个符号上。
- **常见场景**：
  - 第三方库没有类型，需手写 `xxx.d.ts`。
  - monorepo 里路径别名没配好，运行正常但编辑器报红。
  - ESM/CJS 混用时，默认导入和命名导入的类型行为不一致。

### ⚛️ 模块六：框架实战（React/Vue 通用思路）

- **知识点**：组件 Props 建模、事件处理、请求状态建模、表单约束、字典与枚举。
- **模块讲解**：
    - 先为输入输出建模，再写业务逻辑，能减少后期返工。
    - 请求状态建议用可辨识联合，不要多个布尔值互相打架。
    - 字典与枚举用来约束字符串和数值，减少魔法字符串。

#### 6.1 组件 Props 建模

- **讲解**：
    - Props 应该尽量精确约束，避免 `any`。
    - 可选 Props 用 `?`，默认值可用 `= value`。
- **示例**：

```ts
// React
interface ButtonProps {
  children: React.ReactNode;
  onClick: (e: React.MouseEvent<HTMLButtonElement>) => void;
  disabled?: boolean;
  variant?: 'primary' | 'secondary';
}

function Button({ children, onClick, disabled = false, variant = 'primary' }: ButtonProps) {
  return (
    <button onClick={onClick} disabled={disabled} className={variant}>
      {children}
    </button>
  );
}

// Vue
interface Props {
  modelValue: string;
  items: { id: string; label: string }[];
  disabled?: boolean;
}

defineProps<Props>();
```

#### 6.2 请求状态建模

- **讲解**：
    - 避免 `loading: boolean` + `error: string` 的方式，容易产生非法状态。
    - 使用可辨识联合清晰表达状态机。
- **示例**：

```ts
type AsyncState<T, E = Error> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: E };

function useData(url: string): AsyncState<any> {
  const [state, setState] = React.useState<AsyncState<any>>({ status: 'idle' });

  React.useEffect(() => {
    setState({ status: 'loading' });
    fetch(url)
      .then(r => r.json())
      .then(data => setState({ status: 'success', data }))
      .catch(error => setState({ status: 'error', error }));
  }, [url]);

  return state;
}
```

#### 6.3 表单与字典约束

- **讲解**：
    - 表单字段使用精确类型，避免 string 过于宽泛。
    - 字典用 `Record<K, V>` 或 `readonly` 对象。
- **示例**：

```ts
// 表单类型
type LoginForm = {
  email: string;
  password: string;
  remember: boolean;
};

// 字典/常量
const STATUS_LABELS = {
  pending: '待处理',
  done: '完成',
  failed: '失败'
} as const;

type Status = keyof typeof STATUS_LABELS; // 'pending' | 'done' | 'failed'

function getLabel(status: Status): string {
  return STATUS_LABELS[status];
}
```

### 🧪 模块七：排错与类型治理

- **知识点**：常见类型报错定位、`any` 污染防控、运行时校验、类型兼容性、性能优化。
- **模块讲解**：
    - 大多数 "Type X is not assignable to Y" 本质是建模不一致或收窄不足。
    - TS 不能替代运行时校验，外部输入仍需 schema 校验。
    - 过深的递归类型会导致编译变慢。

#### 7.1 常见报错与定位

- **讲解**：
    - "Type X is not assignable to Y"：通常是赋值端类型过宽或接收端过窄。
    - "Property not found"：检查属性名大小写或是否可选。
    - "Cannot find module"：检查导入路径和 tsconfig 配置。
- **示例**：

```ts
// 错误：string 不能赋给 'active' | 'inactive'
const status: 'active' | 'inactive' = 'unknown'; // error

// 正确：先类型守卫
const status: string = 'active';
const refined: 'active' | 'inactive' = status as 'active' | 'inactive';
if (refined === 'active') {
  console.log('is active');
}
```

#### 7.2 any 污染防控与运行时校验

- **讲解**：
    - `any` 一经出现会"传染"，污染相关类型链。
    - 外部输入（API、用户上传）必须做运行时校验。
- **示例**：

```ts
// 污染示例
const x: any = 'hello';
const y: string = x; // 本应报错但 any 污染了
const z: number = y; // 现在 z 是 number 了，虽然实际是 string

// 正确做法：运行时校验
function parseUser(data: unknown): { id: string; name: string } {
  if (typeof data !== 'object' || data === null) {
    throw new Error('User must be object');
  }
  const obj = data as Record<string, unknown>;
  if (typeof obj.id !== 'string' || typeof obj.name !== 'string') {
    throw new Error('User.id and User.name must be string');
  }
  return { id: obj.id, name: obj.name };
}
```

#### 7.3 类型兼容性与性能优化

- **讲解**：
    - 类型兼容性遵循"里氏替换原则"。
    - 过深的递归泛型会导致 TS 编译变慢。
    - 使用 `type` 而非 `interface` 时要注意编译速度。
- **示例**：

```ts
// 类型兼容性
interface Animal { name: string }
interface Dog extends Animal { breed: string }

const dog: Dog = { name: 'Rex', breed: 'Labrador' };
const animal: Animal = dog; // ok，Dog 可赋给 Animal

// 递归类型（谨慎使用）
type DeepPartial<T> = T extends object
  ? { [K in keyof T]?: DeepPartial<T[K]> }
  : T;

// 可能导致编译变慢
type ComplexNested = DeepPartial<{ a: { b: { c: { d: string } } } }>;
```
