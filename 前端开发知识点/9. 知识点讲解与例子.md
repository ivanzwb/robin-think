## 1. JavaScript

### 数据类型与类型转换
- 主章节：`1. JavaScript.md` 模块一
- 30秒回答：类型题我会先给结论：JS 有值语义和引用语义两套行为，很多 bug 来自隐式转换。然后讲判断策略：基础类型用 `typeof`，结构化对象用 `Object.prototype.toString.call`，最后补一个场景，比如表单空值和接口字段比较时避免 `==`，优先显式转换，保证边界稳定。

### 作用域与 this
- 主章节：`1. JavaScript.md` 模块一/二
- 30秒回答：我会把它拆成两层：作用域解决“变量从哪找”，this 解决“函数给谁用”。作用域由定义位置决定，this 由调用方式决定，普通函数可被 `call/apply/bind` 改写，箭头函数继承词法 this。工程上常见价值是避免回调丢 this 和闭包拿错变量。

### 原型与继承
- 主章节：`1. JavaScript.md` 模块一
- 30秒回答：JS 继承本质是原型链复用，不是类实例复制。对象访问属性会沿原型向上查找，`class/extends` 只是语法糖。面试里我会补充一点：原型链过深会影响可维护性，业务中更推荐组合优于继承，继承只用于稳定抽象层。

### 事件循环与异步
- 主章节：`1. JavaScript.md` 模块三/四
- 30秒回答：异步题我按执行模型回答：同步先执行，当前宏任务结束后清空微任务，再进入下一轮。Promise/async 只是写法差异，本质都是任务调度。实践上我会强调两件事：一是微任务堆积会拖慢渲染，二是复杂异步流程要做超时、取消和错误归并，不然线上很难排障。

### JS 引擎与宿主运行时
- 主章节：`1. JavaScript.md` 模块三
- 30秒回答：这一题重点是边界意识：引擎负责语法执行、调用栈和内存管理，宿主提供 DOM、网络、定时器等外部能力。浏览器和 Node 的差异不是 JS 语法不同，而是宿主调度不同，所以同样是事件循环，细节行为会不一致。

### 模块化与 Web API
- 主章节：`1. JavaScript.md` 模块五/六
- 30秒回答：模块化解决依赖组织和可维护性，ESM 因静态结构更利于 Tree Shaking 和按需加载。Web API 是 JS 连接浏览器能力的接口层。工程里常见取舍是：业务模块优先 ESM，能力调用通过 API 封装做隔离，避免平台差异直接泄露到业务代码。

### 调试、性能、安全
- 主章节：`1. JavaScript.md` 模块六/七
- 30秒回答：我会用“定位-优化-防护”三段法。定位靠可复现和调用链证据，优化先抓长任务和关键路径，再做回归验证，安全优先 XSS/CSRF/CSP 和最小权限策略。重点不是背术语，而是能说明发现问题、修复问题、避免回归的闭环。

## 2. TypeScript

### 类型系统基础
- 主章节：`2. Typescript.md` 模块一
- 30秒回答：TS 的核心价值是把错误前移到编译期，降低运行时故障率。`any` 是放弃约束，`unknown` 强制先收窄再使用，`never` 常用于穷尽检查。工程上我会强调：类型不是装饰，而是团队沟通协议，决定多人协作时的变更成本。

### interface vs type
- 主章节：`2. Typescript.md` 模块二
- 30秒回答：两者都能描述对象，但侧重点不同：`interface` 更适合对象契约和可扩展声明，`type` 更适合联合、映射、条件类型。项目里我通常把领域模型用 interface，复杂类型运算用 type，这样可读性和演进性更好。

### 泛型与收窄
- 主章节：`2. Typescript.md` 模块三
- 30秒回答：泛型解决复用时类型不丢失，收窄解决联合类型安全访问。一个负责抽象能力，一个负责落地安全。面试里我会补充场景：请求封装、表单校验、组件 props 都依赖这两个机制来保证复用和正确性。

### 类型体操
- 主章节：`2. Typescript.md` 模块四
- 30秒回答：类型体操本质是把业务约束前移到类型层，用条件类型做分支、infer 做提取、映射类型做批量变换。价值是把“运行时报错”变成“编译期报错”，但要控制复杂度，避免类型系统本身成为维护负担。

### 工程配置
- 主章节：`2. Typescript.md` 模块五
- 30秒回答：TS 成效的上限在配置，不在语法。`strict` 是底线，`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes` 这类选项决定风险暴露程度。声明文件治理决定第三方依赖是否可控，配置统一程度直接影响团队交付稳定性。

### 编译器、控制流分析与模块解析
- 主章节：`2. Typescript.md` 模块一/三/五
- 30秒回答：TS 在 check 阶段做符号和控制流分析，在 emit 阶段擦除类型，所以类型安全主要发生在构建时而非运行时。模块解析问题常是“代码能跑但类型找不到”，要从 tsconfig、package exports/types、路径别名三层定位。

## 3. Angular

### 组件体系
- 主章节：`3. Angular.md` 模块一
- 30秒回答：Angular 组件体系的核心是模板和类职责分离，模板表达视图，类承载状态与行为。生命周期不是背钩子顺序，而是在正确阶段做初始化、订阅和清理，减少副作用和内存泄漏。

### DI 与服务
- 主章节：`3. Angular.md` 模块二
- 30秒回答：DI 的价值是把对象创建和业务使用解耦。组件只声明依赖，由注入器按作用域解析，便于测试替身和模块隔离。面试里我会补一句：局部 provider 覆盖 root provider 是做多租户/多实例隔离的关键手段。

### 路由与表单
- 主章节：`3. Angular.md` 模块一/五
- 30秒回答：路由负责页面组织和权限边界，Reactive Forms 负责复杂状态和校验一致性。中后台场景里这两块决定开发效率和错误率，实践上要配合守卫、异步校验和错误态可视化。

### 变更检测与性能
- 主章节：`3. Angular.md` 模块四
- 30秒回答：默认变更检测稳但成本高，OnPush 通过引用变化降低无效检查。优化关键不是手动“跳过一切”，而是建立清晰的数据不可变边界，让变更触发路径可预测。

### Signals 与现代特性
- 主章节：`3. Angular.md` 模块三/五
- 30秒回答：Signals 提供细粒度响应式更新，Standalone 降低模块样板。组合价值是更少框架噪音和更可控更新路径。实践里要关注 signal 与 RxJS 的边界，避免双状态源造成一致性问题。

### Ivy、DI 查找链与 Signals 更新机制
- 主章节：`3. Angular.md` 模块二/三/四
- 30秒回答：Angular 不走虚拟 DOM 路线，而是 Ivy 编译后直接驱动渲染指令。DI 决定依赖查找路径，Signals 决定更新唤起粒度。三者组合形成 Angular 的性能模型：编译期减负、运行时精确更新、依赖层级可控。

### Angular 测试实践
- 主章节：`3. Angular.md` 模块六
- 30秒回答：Angular 测试要围绕业务行为而不是框架细节。TestBed 组装环境，Fixture 驱动渲染，断言用户可见结果。高质量测试还要覆盖依赖替身、异步稳定性和组件销毁清理路径。

## 4. 自动化测试

### 测试分层
- 主章节：`4. 自动化测试.md` 模块一
- 30秒回答：测试分层本质是成本分配问题。单测负责快反馈，集成测试负责协作正确，E2E 负责关键流程兜底。真正有效的策略是“高风险优先”，不是追求某一层覆盖率绝对高。

### 单测与组件测
- 主章节：`4. 自动化测试.md` 模块二/三
- 30秒回答：单测和组件测要测行为契约，不测实现细节。Mock/Spy 只隔离边界，不应掩盖真实风险。好测试的标准是失败信息可定位、断言和业务风险强关联。

### E2E 与自动化
- 主章节：`4. 自动化测试.md` 模块四
- 30秒回答：E2E 价值在端到端信心，不在数量。优先覆盖登录、下单、支付这类核心路径，保证可复现、可等待、可诊断。策略上要结合分环境执行和失败回放，不然成本会失控。

### BDD 与 Cucumber
- 主章节：`4. 自动化测试.md` 模块五
- 30秒回答：BDD 不是语法工具，而是协作机制。它让产品、测试、研发共享业务语言，降低需求歧义。适用于高价值流程对齐，不适合拿来覆盖底层技术细节。

### 稳定性与 CI
- 主章节：`4. 自动化测试.md` 模块六/七
- 30秒回答：稳定性核心是消除不确定性：禁止盲目 sleep、控制测试数据、固定环境依赖。CI 上用分层流水线平衡速度和质量，PR 快反馈，主干做重保障，夜间做全量回归。

## 5. 浏览器

### 渲染流程
- 主章节：`5. 浏览器.md` 模块一
- 30秒回答：渲染不是一步到位，而是解析、布局、绘制、合成的流水线。优化重点是减少高成本阶段触发，尤其避免频繁回流和大面积重绘，把动画尽量放到合成阶段。

### 网络协议
- 主章节：`5. 浏览器.md` 模块二
- 30秒回答：协议演进关注真实收益：HTTP/2 提升并发复用效率，HTTP/3 改善弱网稳定性，TLS 提供机密性与身份可信。面试里要能把协议能力和首屏体验、弱网表现挂钩。

### 存储与安全
- 主章节：`5. 浏览器.md` 模块三
- 30秒回答：存储选型看生命周期、容量和安全边界。Cookie 适合服务端协同，localStorage 适合前端持久化，敏感信息避免裸存。安全上要形成组合防线：输入转义、CSP、SameSite、CSRF token。

### 缓存与加载
- 主章节：`5. 浏览器.md` 模块四
- 30秒回答：缓存策略不是只提 max-age，而是强缓存、协商缓存、SW/CDN 分层配合。核心目标是命中率、更新一致性和故障可降级三者平衡。

### 线程与性能
- 主章节：`5. 浏览器.md` 模块五/六
- 30秒回答：主线程是稀缺资源，长任务会直接拖垮交互指标。优化思路是拆分任务、异步让步、必要时迁移 Worker，并用真实指标验证改善而不是只看主观流畅度。

### 浏览器进程/线程与交互链路
- 主章节：`5. 浏览器.md` 模块五
- 30秒回答：INP 差通常是链路问题，不是单函数问题。输入事件到下次绘制要经过脚本执行、布局绘制、合成提交，任一环过重都会卡。定位必须看整条链路证据。

## 6. DevTools

### 基础面板
- 主章节：`6. DevTools.md` 模块一
- 30秒回答：DevTools 能力核心是“症状到面板映射”。样式异常看 Elements，逻辑错误看 Sources，请求问题看 Network，卡顿看 Performance，内存涨看 Memory，先分型再动手。

### 常见排障路径
- 主章节：`6. DevTools.md` 模块三/四/五
- 30秒回答：排障要流程化：先稳定复现，再采集证据，再验证假设。接口慢看 Timing，交互卡看 Long Task，内存涨看 Retainers。避免边试边猜，减少无效排查时间。

### 线上问题定位
- 主章节：`6. DevTools.md` 模块六
- 30秒回答：线上定位关键是“还原现场 + 串联链路”。Source Map 负责代码还原，traceId 负责跨端关联，回放负责用户路径还原，三者结合才能稳定复盘问题。

### CDP、Trace Event 与 sourcemap 失效排查
- 主章节：`6. DevTools.md` 模块一/四/六
- 30秒回答：DevTools 底层是 CDP，Performance 本质是读取 trace events。sourcemap 失效优先查一致性：release、build id、hash、上传版本、CDN 路径、部署时间窗，别一开始就怀疑平台工具。

## 7. React / Vue 概念与原理入门

### React 入门
- 主章节：`7. React-Vue 概念与原理入门.md` 模块一
- 30秒回答：React 的核心是状态驱动视图。组件每次渲染产出新的 UI 描述，Diff/调和控制真实 DOM 变更成本。列表必须稳定 key，否则会引发状态错位和渲染异常。

### Vue 入门
- 主章节：`7. React-Vue 概念与原理入门.md` 模块二
- 30秒回答：Vue 的优势是响应式直观和模板表达高效。Vue3 通过 Proxy 追踪依赖，Composition API 提升逻辑复用。面试里我会强调“依赖追踪 + 调度更新”的机制闭环。

### React vs Vue
- 主章节：`7. React-Vue 概念与原理入门.md` 模块三
- 30秒回答：两者都能做现代工程，差异在更新模型和心智负担。React 偏显式状态流和函数式组合，Vue 偏模板友好和自动依赖追踪。选型要结合团队能力、历史包袱和交付节奏。

### Fiber、batching、scheduler 与 Vue 响应式调度
- 主章节：`7. React-Vue 概念与原理入门.md` 模块一/二/五
- 30秒回答：React 和 Vue 都做批处理，但路径不同。React 通过更新入队和调度分阶段执行，Vue 通过依赖追踪和 job 队列合并刷新。面试重点不是 API，而是说明“为什么它能减少无效渲染”。

## 8. 工程化、架构设计与线上可观测性

### 工程化
- 主章节：`8. 工程化、架构设计与线上可观测性.md` 模块一
- 30秒回答：工程化的本质不是堆工具，而是把质量和效率制度化。开发阶段要快反馈，发布阶段要稳可追溯，通过门禁和流水线把优秀实践变成默认行为。

### Monorepo 实战
- 主章节：`8. 工程化、架构设计与线上可观测性.md` 模块一/二
- 30秒回答：Monorepo 的收益来自统一依赖、统一规范和增量构建，风险来自边界不清和全仓耦合。落地关键是任务图、缓存键、发布边界三件事做对。

### 架构设计
- 主章节：`8. 工程化、架构设计与线上可观测性.md` 模块三
- 30秒回答：架构题核心是边界和取舍，不是概念堆砌。分层保证可维护，状态流保证可理解，微前端只在组织复杂度足够高且治理能力到位时才值得引入。

### 可观测性
- 主章节：`8. 工程化、架构设计与线上可观测性.md` 模块四
- 30秒回答：可观测性的目标是“从告警到根因”的最短路径。日志、指标、链路要统一语义和关联键，否则数据很多但无法决策。真正价值在快速定位和验证修复。

### 增量构建、远程缓存与 Source Map 一致性
- 主章节：`8. 工程化、架构设计与线上可观测性.md` 模块一/四
- 30秒回答：工程化最难是结果可信。增量构建提速度，远程缓存提复用，source map 保可还原，但都依赖输入指纹和发布元数据强一致，一旦 release/hash/map 对不上，排障会失真。

### 高级性能方法论
- 主章节：`8. 工程化、架构设计与线上可观测性.md` 模块五
- 30秒回答：性能治理要形成闭环：分层诊断、针对性优化、自动化防回归。没有预算阈值和门禁，优化成果通常会在后续迭代中被覆盖掉。

### 稳定性治理
- 主章节：`8. 工程化、架构设计与线上可观测性.md` 模块六/七
- 30秒回答：稳定性不是一次修复，而是机制建设。要同时建设发布前防线、发布后观察、事故后复盘，把经验沉淀成流程和平台能力，降低重复事故概率。
